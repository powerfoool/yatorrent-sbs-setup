# YaTorrent SBS: worker и координатор

Два режима на целевой машине: **worker** исполняет разметки; **координатор** получает пары выдач, отправляет задания, собирает оценки и записывает согласованный результат. По умолчанию машина координатора также исполняет очередь Codex: сначала общая установка worker, затем дополнение координатора.

Считай, что пользователь впервые работает с навыком. Объясняй цель каждого вопроса, предлагай рекомендуемый выбор и 1–2 понятные альтернативы; разрешай свой вариант. Не спрашивай про внутренние поля, версии контрактов или профили, не объяснив зачем они нужны. Нужные сведения спрашивай вместе, уже выданные разрешения не запрашивай повторно. Пример: «Куда записать результаты? Рекомендую итог в существующую колонку оценки, подробности — в комментарий. Можно выделить отдельные колонки для качества и причин выбора». При настройке объясни, что файл подключения даёт доступ к очереди, а вход Google — к выбранной таблице.

Архив r6 публичный, без credentials. На другой машине нет обязательных локальных навыков, сохранённого входа или файлов автора. Все пути вычисляй на целевой машине. Получи внешний приватный AIM2-файл владельца с правами 0600, вне каталога навыка; не выводи содержимое. [Профиль](references/profile.md).

## Общая установка

1. Проверь SHA-256 ZIP, распакуй его, прочитай [setup.md](references/setup.md). Нужен Python ≥3.10 и macOS Apple Silicon. До общей установки проверь `python3 --version`; если Python отсутствует или старше, установи текущий Python через имеющийся Homebrew и запускай scripts этим interpreter. Первичная установка Homebrew/Command Line Tools может требовать действия владельца.
2. Выполни `python3 scripts/install.py --plan`. Только поручение установить/перенастроить эту машину разрешает `--apply`; подготовка ZIP и тестирование пакета не разрешают запуск установки. Существующие активные чужие задания не прерывай.
3. Выполни `python3 scripts/install.py --apply --profile /absolute/private/profile.aim2`. Установщик выбирает последний стабильный официальный YaTorrent, сверяет SHA-256 и проверенный нативный контракт 0.3.9. При изменении контракта остановится для проверки новой версии, не откатится молча на старую. Node24.21.0, Codex0.162.1, Playwright1.64.0 и Chromium156.0.8078.4 закреплены отдельно.
4. Штатное приложение остаётся неизменным. Создаются приватные исполняемые файлы вне приложения и `executor-runtime.json` в штатных данных YaTorrent: launcher, таймаут1800 и требуемый `sbs-codex-v1`. Значение concurrency по умолчанию4 задаётся настройками YaTorrent; 11 агентов на задание задаются Codex launcher. [Разделение настроек](references/setup.md).
5. `startup.py` импортирует профиль через приложение и safeStorage при остановленном worker, очищает resumeAfterUpdate и подтверждает новый зашифрованный профиль. Автообновление приложения сохраняет выбор владельца. Вход Codex выполняется на этой машине: реальный CLI из install-config с `CODEX_HOME=auth_home`, `-c cli_auth_credentials_store="file" login --device-auth`. Владелец завершает вход. При `awaiting_codex_login` после входа повтори `startup.py --root ROOT`.
6. Перед обычным открытием включаются «Принимать Codex» и «Запускать worker при открытии приложения». Обязательный `verify.py --pre-launch` без skip запускает настоящий Codex, Chromium и оба reader; статус пока «подготовлен». Затем приложение открывается и обязательно проверяется действующий нативный worker: PID, executable, свежие метрики, launcher, контракт, fingerprint, timeout1800, concurrency4, ready/accepting и отсутствие требования перезапуска.
7. Только после обеих стадий статус «готов» и `root/verification.json`. При диагностике полная `verify.py --root ROOT` без skip должна вернуть0; exit0 Codex или наличие конфиг-файла сами по себе недостаточны. `--runtime-only`, `--pre-launch` и skip не подтверждают готовность worker или доставку через broker. [Доказательства runtime](references/runtime.md).

Для четырёх jobs возможны 44 агента и до40 браузеров; это настроенный предел, не доказанный параллельный запуск. Настройка `--worker-concurrency 1..16` меняет только число jobs. Таймаут1800 относится к одному Codex-элементу; не ко всей доставке результата. В обычной разметке одна пара — один task/элемент.

Постоянный root по умолчанию `~/.local/share/yatorrent-sbs`; доверенные пути executable/script без пробелов и shell-метасимволов. Установщик отклоняет неподходящий root до изменений. Агентам выдавай простые готовые команды без кавычек. Allow остаются точными для private Node + fixed script, без общего Node/shell/произвольного JS. Chromium sandbox и TLS включены. Не использовать yolo/full-access, не отключать Gatekeeper, не переподписывать приложение.

## Координатор

При поручении настроить координатора прочитай [coordinator.md](references/coordinator.md). После общей настройки запусти `python3 scripts/coordinator_setup.py --plan`, затем `--apply`. Он установит Google Workspace CLI при отсутствии, поставит самостоятельную приватную обёртку `gwsx work` и проверит местную авторизацию. Путь `root/bin/gwsx` добавь в PATH этой сессии; глобальную сломанную обёртку не перезаписывай. Для входов/результатов в локальных файлах используй `--no-google`.

Владелец настраивает свой OAuth-клиент и завершает Google-вход на целевой машине. Пакет не содержит OAuth client JSON, токенов и аккаунта автора. Google-инструменты нужны только координатору; бригадир и разведчики Google не используют. Успешный setup дополнения не заменяет полную worker verify, чтение выбранной таблицы и согласование записи.

Перед отправкой разметок координатор согласует с пользователем формат результата, поля итогового JSON, колонки и допустимые изменения таблицы. Предложи существующие verdict/comment колонки либо удобную декомпозицию JSON в отдельные поля. Покажи пример одной строки с итогом и причинами. Согласие сохраняется в локальном плане; оно охватывает последующие записи в эти диапазоны, повторно каждую строку не спрашивай. Изменение структуры/перезапись существующих результатов требует соответствующего согласованного выбора.

Далее: прочитай пары; подготовь по1 SBS/task с переносимыми инструкциями бригадира/разведчиков; отправь через проверенный API брокера; отслеживай доказанные состояния; принимай/сохраняй результаты; по мере завершения заполняй согласованные диапазоны через `gwsx work`. Чужие результаты общей очереди не подтверждай автоматически. Ограничения очереди и восстановления: [broker.md](references/broker.md).

## Назначение бригадиру

Координатор передаёт HTML двух SERP, query/region/device, при наличии top5, тексты рубрики и scout-инструкций, согласованную output_schema. Обход URL выполняют разведчики; бригадир распределяет задания и оценивает пару. Промпты включай текстом, по умолчанию: пути координатора не доступны другой машине.

Каждый worker обнаруживает собственную установленную среду. `--sbs-print-config` выдаёт descriptor с его локальными entry_points; команды оценки получают из этой установки, не из verification.json координатора. Reader-файлы — только при отдельной доставке `prompts/foreman.md`/`prompts/scout.md` в workspace задания. [Файлы промптов](references/prompts.md), [браузер](references/browser.md).

Передай уже данное разрешение CAPTCHA в область назначенных URL. Инструмент не снимает ограничений системы и не гарантирует CAPTCHA. ordinary — основной режим; metadata_only только для конкретного URL после доказанной неудачи/барьера, с неизвестными фактами без выдуманных оценок. Не включай YaTorrent «только вложенные материалы» для живого обхода: это запрещает web-fetch.

Заверши понятным отчётом: что настроено, какие входы владельца ещё нужны, прошёл ли реальный браузер, подтверждён ли worker и готов ли координатор к выбранной таблице. Не называй отправленные задания работающими без доказательств; broker end-to-end проверяется отдельным реальным тестом. Для сборки r6 все реальные broker/Sheets writes остаются выключенными.
