# YaTorrent SBS: подготовка macOS worker

Работай на машине, которая будет исполнять задания. Этот архив устанавливает инфраструктуру; промпт оценки SERP координатор передаёт отдельным заданием. Не используй пути, инструкции или авторизацию машины автора архива.

Поддерживается macOS **Apple Silicon**. Для Intel этот релиз YaTorrent не заявлен. Релиз r5 можно публиковать: AIM2-профиль и credentials в него не включены. Получи отдельный локальный AIM2-файл от владельца; не выводи его содержимое и не передавай профиль LLM. Храни файл вне каталога навыка с правами 0600. Требования: [references/profile.md](references/profile.md). Программа читает профиль локально, приложение импортирует его через safeStorage.

## Установка

1. Проверь SHA-256 архива, если его передал координатор. Выполняй scripts из распакованного навыка, не из ZIP. Нужен Python 3. Если `python3` отсутствует, установи его штатно через имеющийся Homebrew (`brew install python`); не запускай случайный bootstrap из интернета. Отсутствие Homebrew/Command Line Tools — этап первоначальной настройки macOS, который может потребовать действия владельца.
2. Прочитай [параметры установки](references/setup.md). Выполни `python3 scripts/install.py --plan`. Сопоставь план с текущей машиной. При существующем работающем YaTorrent сначала штатно останови worker и приложение, если пользователь поручил перенастройку этой установки. Не прерывай чужие задания и не подменяй другую активную установку.
3. Когда пользователь поручил **установить/настроить** worker, выполни `python3 scripts/install.py --apply --profile /absolute/private/profile.aim2`. Одно поручение на установку охватывает перечисленные в плане установки и настройку launcher’ов. Если пользователь просит только подготовить ZIP/проверить план, `--apply` не выполняй.
4. Установщик определит **последний стабильный YaTorrent** через официальный GitHub Releases API, проверит SHA-256 и неизменность проверенного контракта адаптера, затем установит приложение в пользовательский `Applications`, приватные Node.js/Codex CLI, Playwright и полный Chromium. `startup.py`, автоматически вызываемый установщиком, импортирует предоставленный внешний `.aim2` через приложение и safeStorage. Он проверяет обновление зашифрованного файла и совпадение **публичных** полей, сохраняя локальную квитанцию импорта; существующий профиль с такими же публичными полями не заменяет подтверждение импорта текущего файла.
5. Проверь авторизацию Codex. Используй реальный CLI из install-config.json, с `CODEX_HOME` установленным на auth_home. Если требуется вход с сохранением credentials в файле, выполни реальный CLI с `-c cli_auth_credentials_store="file" login --device-auth`. Вход завершает владелец аккаунта; не копируй его credentials с другой машины. `login status` проверяй после входа. Если установщик вернул `awaiting_codex_login`, после входа выполни `python3 scripts/startup.py --root <каталог установки>`. Launcher не извлекает секреты из Keychain и не сохраняет auth в рабочих каталогах после задания.
6. Перед обычным запуском `startup.py` включает «Принимать Codex» (`consume_codex=true`) и «Запускать worker при старте приложения» (`autoStart=true`), затем вызывает **`verify.py --pre-launch` без skip**. Это обязательная проверка инфраструктуры с настоящим Codex/Chromium, но её статус — «подготовлен», `delivery_ready=false`, `worker_ready=false`. Только после её успеха приложение открывается без `.aim2`.
7. После открытия приложения `startup.py` обязательно подтверждает **фактический worker**: новый launch receipt, живой PID и executable установленного worker, хэш конфигурации, использованной при exec, launcher Codex, `timeout_seconds=1800`, concurrency=4 по умолчанию (либо выбранный `--worker-concurrency`) и работающий приём Codex. Метрики должны принадлежать тому же PID, быть свежими и продвинуть heartbeat/uptime между двумя наблюдениями. Обычный Codex, таймаут 180, старый PID/файл или один свежий metrics.json не подтверждают готовность. При неудаче программа возвращает ненулевой exit и «не готов»; открытое приложение честно отмечается `app_launch_requested=true`. Она отключает будущий autoStart на диске, но не убивает чужие процессы и не перезапускает jobs автоматически.
8. Только после обеих стадий результат — «готов», `delivery_ready=true`, `worker_ready=true`; полный отчёт сохраняется в `root/verification.json`. Отдельно `python3 scripts/verify.py --root <каталог установки>` без skip выполняй при диагностике или повторной приёмке: он требует как инфраструктуру, так и действующий worker. Сразу повторять тот же платный Codex smoke после успешного `startup.py` не нужно.

Инфраструктурная проверка запускает Chromium **внутри настоящего Codex через установленный launcher** с worker flags, проверяет оба prompt reader, 11 слотов, workspace-write, сеть, фактическую approval_policy и очистку auth-ссылки. Анализируются результаты команд и rollout: exit 0 самого Codex не доказывает успех браузера. `--runtime-only`, `--pre-launch` и skip-флаги отдельно не подтверждают готовность worker или broker end-to-end. `--pre-launch` не совмещается с skip.

Первичный импорт — отдельный технический запуск приложения с `autoStart=false`: YaTorrent проверяет автозапуск **до** импорта переданного `.aim2`. Для 0.3.5 программа также очищает resumeAfterUpdate и выключает autoUpdate, чтобы старый профиль не запустился при импорте, а автоматическое обновление не заменило адаптер. После подтверждения импорта программа штатно закрывает приложение, включает обе нужные опции, проводит инфраструктурную проверку, запускает приложение обычным способом и подтверждает действующий worker. Подробности и ограничения последнего релиза — [references/setup.md](references/setup.md).

Постоянный root по умолчанию — `~/.local/share/yatorrent-sbs`. Executable и fixed scripts должны находиться по доверенным абсолютным путям без пробелов и shell-метасимволов. Для другого root установщик проверяет это **до изменений** и отклоняет неподходящий путь. Передавай агентам готовые `browser_command_string` и `prompt_reader_command_string`, без кавычек, подстановок и shell-обёрток. Не переносить новое правило на старые entry points в `Library/Application Support`.

В конфигурации **11 агентов всего: бригадир + 10 разведчиков**. `agents.max_concurrent_threads_per_session=10` считает только разведчиков. YaTorrent по умолчанию принимает **четыре задания одновременно** (`--worker-concurrency 1..16`, значение сохраняется в install-config и применяется при каждом запуске worker), тайм-аут Codex — **1800 секунд**. При четырёх jobs доступно до 44 агентов и 40 браузеров. Это отдельные лимиты: увеличение количества broker jobs умножает число браузеров.

## Что изменяют launcher’ы

Точный контракт и причины адаптера: [references/setup.md](references/setup.md).

- Worker launcher применяет binary Codex, тайм-аут и число одновременных jobs **до** чтения конфигурации worker. Не используй файловый watcher с гонкой при старте.
- Codex launcher сохраняет модель, JSON Schema, input/output протокол, `workspace-write` и сеть; удаляет `--ephemeral`, включает разведчиков и отключает посторонний project bootstrap. Служебное состояние CLI лежит в отдельном каталоге **каждого задания**. Это состояние CLI, а не обязанность бригадира/разведчика писать отчёты в файлы.
- В правила Codex добавляются точные префиксы фиксированных browser launcher и prompt reader. Reader читает только `prompts/foreman.md` или `prompts/scout.md` в каталоге задания. Существующие правила остаются; более строгие ограничения сохраняют приоритет. Не разрешай общий `node`, `node -e`, shell, Playwright evaluate или произвольный JS.
- Chromium использует чистый контекст, TLS-проверку и собственный sandbox. Полный Chromium поддерживает `--headed`; оконный режим требует активной GUI-сессии macOS. Headless доступен без открытого окна.

Адаптер находится в приватной установке приложения, сохраняет оригинальный worker и заново подписывает bundle ad-hoc. Не отключай Gatekeeper и не удаляй quarantine. Если macOS требует разрешить открытие, владельцу нужно штатно разрешить конкретное приложение. Обновление YaTorrent может заменить адаптер. Установщик не откатывается на старую версию: если последний релиз меняет проверенные модули или worker, остановись и адаптируй навык по первичным ресурсам нового релиза перед установкой. Codex CLI при этом остаётся закреплённым; его не обновлять вместе с YaTorrent вслепую.

## Перед запуском SBS-задания

После установки координатор должен включить в задание **готовую browser_command_string** из успешной полной verify и минимальную инструкцию из [references/browser.md](references/browser.md). Executable и script не заключаются в кавычки. У другой машины будут другие пути. Бригадир распределяет URL, **разведчики** открывают сайты и возвращают оценки сообщениями.

Если промпты передаются файлами, доставь их в `prompts/foreman.md` и `prompts/scout.md` внутри каталога задания до запуска агентов. Для чтения используй готовые строки `prompt_reader_example_strings.foreman` и `.scout` из отчёта проверки без кавычек; назначение должно содержать команду и рабочий каталог. Формат и область разрешения описаны в [references/prompts.md](references/prompts.md). Тексты оценочных промптов в этот установочный ZIP не включены.

Разрешение пользователя на CAPTCHA передавай в назначение разведчика с областью действия конкретного запуска. Launcher позволяет click/drag по свежим наблюдениям; он не снимает ограничения системы и не гарантирует прохождение каждой CAPTCHA. Если контент не получен после разрешённых попыток, агент указывает реальный барьер; `metadata_only` — резерв, без выдуманных оценок качества и полезности.

Подготовка ZIP и `--plan` не включают broker intake. Поручение **установить/настроить worker** с этим навыком включает настройку приёма Codex, автозапуска и запуск приложения после профиля/авторизации/инфраструктурной проверки; завершение установки требует ещё проверки действующего worker. Перед `--apply` учти, что успешная установка начнёт приём доступных заданий. Сама verify приём не запускает. Готовность имеет область `local_worker_only`; `broker_end_to_end_verified=false` и `parallel_jobs_verified=false` сохраняются до отдельного подтверждения. Диагностика 0.3.4 и заявленные исправления 0.3.5: [references/broker.md](references/broker.md). Полный end-to-end считается проверенным только после реального назначения, исполнения и получения результата — не по одному флагу `consume_codex`.

Задания с живым обходом должны явно разрешать переходы по назначенным URL. Не помещай такой обход в режим YaTorrent «только вложенные материалы»: он добавляет запрет на web-fetch. Переданный HTML выдач и списки URL можно включить обычным текстом в prompt/input_data.

Заверши коротким отчётом: установленные версии, импорт профиля, авторизация, browser smoke, правило, 11 слотов, тайм-аут/concurrency, фактическая политика разрешений или её непроверенность, путь launcher для заданий и состояние worker (подготовлен/запущен/проверен через broker).

Не предлагай смену approval_policy как исправление диагностированного сбоя кавычек. Значение `untrusted` закреплённый CLI отвергает; проба `on-request` через exec -c в предоставленной диагностике оставила фактический never. Каталог rules продолжает связываться симлинком; пустой config.toml и копирование rules для этого исправления не требуются. CLI не обновляй вслепую: сначала подтвердить исправление контрольными A/B/C, затем отдельно изменить pin и integrity. Диагностика и границы доказательств: [references/runtime.md](references/runtime.md).
