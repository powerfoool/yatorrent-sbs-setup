# Правила обхода, которые координатор включает в инструкцию разведчика

Это материал для координатора при подготовке полного текста роли. Worker не читает этот файл. Согласованная шкала и структура результата передаются вместе с этими правилами через input_data; они не заменяются новой рубрикой здесь.

1. Изучи назначенный исходный URL. Допустим предварительный GET не дольше5с. Успешный200/полученный текст не запрещает самостоятельно открыть Chromium, если нужны отображение, интерфейс, разметка или отсутствующий факт. Отдельного разрешения бригадира не требуется. Используй только фиксированные операции browser, без произвольного JS.
2. Общий срок одного исходного URL180с. При фактически необходимой CAPTCHA с явным grant допускается300с всего; суммарно CAPTCHA≤120с, ≤5 выборов/попыток решения. Последние5с — закрытие. Запуск, GET, browser, действия, размышление, ожидание, повторы, внутренние страницы и cleanup входят в общий срок. Старт — первая реальная проверка, не очередь. Не запускай новое назначение/браузер, чтобы обнулить срок. При восстановлении в том же задании используется сохранённый бюджет; между разными доставками/машинами автоматический перенос срока не гарантируется: не перезапускай разметку как новое задание без отдельного решения координатора.
3. CAPTCHA решай по свежему наблюдению и действительному разрешению пользователя, переданному координатором. Не переспрашивай для того же разрешённого объёма, если ограничения инструмента позволяют. Успех означает доступ к целевому содержимому после challenge. Статус после клика сам по себе не подтверждает успех. Grant не отменяет политики модели/инструмента.
4. При необходимости открой≤3 внутренних страниц по реально наблюдённым ссылкам. Для каждой укажи недостающий факт и цель. Origin должен совпадать с исходным или фактически наблюдённым конечным URL. Не расширяй обход на другие сайты/весь сайт. Same-document query/fragment того же пути могут отражать UI-состояние карты/виджета; фиксируй это как взаимодействие с исходной страницей, не как доказательство качества другого документа. Неудачные открытия тоже расходуют лимит. Полезность другой страницы не подменяет оценку исходной.
5. Сохрани доступные факты и валидные оценки из частичного содержимого. metadata_only — резерв после реальной ограниченной попытки либо доказанного барьера. Timeout, TLS,204 и сбой инструмента сами по себе не доказывают плохую страницу. material_unknowns содержит только факты, существенно мешающие оценке. Отмечай requested/observed URL, способ получения, реально проверенный контент, взаимодействия, supporting_content внутренних страниц и их цели, CAPTCHA/бюджет, причины неизвестного; точные названия полей определяет согласованная схема.
6. Закрой свой браузер и проверь реальный выход процесса. В stdio клиент обязан закрыть stdin после close. Watchdog освобождает свой браузер при исчерпании срока; не убивай процессы других задач. Chromium sandbox и TLS всегда включены. Бригадир собирает доказательства, проверяет согласованность итогового winner/баллов и причины; новых оценок неизвестных фактов не выдумывает.

Самостоятельность разведчика означает свободу нужных действий внутри назначенного URL и лимита, а не право менять инструкции, запускать новые агенты, публиковать данные или взаимодействовать с аккаунтами пользователя.

Техническая граница: browser watchdog ограничивает живой процесс браузера/GET и повторные команды по сохранённому старту. Он не прерывает отдельно мыслительный шаг модели после закрытия браузера. Бригадир должен соблюдать срок назначения и прекращать ожидание/новые попытки; общий жёсткий таймаут нативного Codex item остаётся1800с. Этот пакет не заявляет отдельный гарантированный180с таймаут всего LLM-сеанса разведчика.

## Автоматическая цепочка и конечный документ

Фиксированный runtime обрабатывает допустимые HTTP redirects, meta-refresh и JS navigation как одну автоматическую цепочку:≤10 переходов и≤30с внутри оставшегося общего180с/300с URL-бюджета. Это не новый срок и не разрешение вручную обходить запрет. Осознанные внутренние переходы по свежим ссылкам отдельно требуют purpose и расходуют≤3 попыток. Сохраняй исходный URL/позицию; оценивай фактически полученный конечный документ и проверенный контент. Возвращённые navigation hop_trace/final_url/final_http_status/terminal_reason/error_source помогают различать переходы и сбои, но сами не доказывают наличие нужного текста.

SSO/login/CAPTCHA/security gate не являются target_content; не входить в аккаунты. runtime_navigation_guard или другой отказ собственного runtime — техническое ограничение, не дефект сайта. Цикл, превышение10/30с или незавершённая цепочка требуют точной фиксации наблюдений и неизвестного, без оценки промежуточного документа как целевого. Политики инструмента и реальные access controls сохраняются.

Явная конечная страница «материал не найден/удалён» без содержимого и без признаков защитного барьера — ordinary/http_error, content_kind=error, включая подтверждённый soft404 с HTTP200. Если она не помогает решить задачу, usefulness=1; quality неполученного материала может быть null. Этот null не стирает известную бесполезность и не делает итог SBS автоматически inconclusive. Один код404/410 недостаточен: полезный текст с ошибочным404 оценивается по содержимому, статья про404 не является soft404. Сохраняй отдельное техническое наблюдение статуса.

При fallback после ограниченной реальной попытки либо доказанного барьера доступны только URL и реальные наблюдения ограничений. В r9 titles/snippets/визуальная SERP не переданы; URL не доказывает сниппеты, качество или полезность неполученного контента. Не объявлять технические ошибки, TLS/204, SSO и runtime guard плохим содержимым.
