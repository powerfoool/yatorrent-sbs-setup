# Проверка настоящего Codex-маршрута

В предоставленной диагностике macOS arm64 с закреплёнными версиями воспроизведён триггер, связанный с shell-кавычками и применением узкого allow:

| Контроль | Команда | Результат на целевом Mac |
|---|---|---|
| A | Безопасные абсолютные executable/script без пробелов, без кавычек | exit_code=0, ok=true, SBS_CHROMIUM_ALLOW_OK |
| B | Те же пути, каждый в одинарных кавычках | exit_code=1, Chromium SIGABRT, cleanup kill EPERM |
| C | Пути через Library/Application Support в кавычках | Такой же отказ |

A также прошёл с исходным codex-launcher, штатным --ignore-user-config, symlink rules, workspace-write, фактическим never, Chromium sandbox и TLS. Внутренняя причина CLI не локализована. Эта версия пакета использует проверенный маршрут A; не объявляет B/C исправленными в CLI. Доказательства A/B/C предоставлены владельцем целевого Mac. При сборке нового ZIP не требуется воспроизводить заведомо сбойный маршрут.

Инфраструктурная стадия `python3 scripts/verify.py --pre-launch --root ROOT` сначала проверяет установленную инфраструктуру, приватный app adapter, byte-exact AIM2, зашифрованный импорт, file-auth, точные allow и entry paths. Затем обязательно выполняет runtime smoke через установленный Codex launcher. Это короткий оплачиваемый/учитываемый подпиской Codex-вызов, поэтому он нужен для приёмки установки, а не для каждого URL.

Smoke создаёт отдельный каталог задания и два контрольных UTF-8 файла со случайными маркерами. Использует модель из публичного Codex-раздела профиля и фактический протокол запуска worker: exec, workspace-write, --ignore-user-config, --ephemeral во входных flags, --skip-git-repo-check, color never, approval_policy=never, network_access=true, output_schema/output-last-message, prompt на stdin. Существующий launcher удаляет ephemeral и изолирует состояние. Разрешения и user config не подменяются.

Агент выполняет ровно три простые команды: browser --check, reader foreman, reader scout. Проверка анализирует реальные вызовы и результаты из rollout, связывает их по call_id и сверяет точные команды. Все три exit_code должны быть 0; browser должен вернуть ok=true, контрольный readback, закреплённые версии, Chromium sandbox=true, TLS=true; оба reader должны вернуть собственные случайные маркеры. Финальный ответ агента не заменяет tool evidence.

Из контекста настоящего сеанса проверяются 11 слотов, workspace-write, network_access=true и фактическая approval_policy. Политика указывается отдельно от requested never. Проверяется удаление временного auth.json; его содержимое не читается и не выводится. Неполные, неоднозначные, отсутствующие доказательства, timeout, browser exit1 даже при Codex exit0 и пропущенные проверки не дают статуса «готов».

`--runtime-only` служит отдельной диагностикой этого маршрута и явно не подтверждает полную установку. Skip-флаги сохраняются для диагностики, но не удовлетворяют критерию готовности. Полная verify при обязательной неудаче возвращает ненулевой код и «не готов». Сама verify не включает broker intake. `startup.py` вызывает инфраструктурную стадию перед открытием приложения, затем проверяет фактический worker. `--pre-launch` возвращает «подготовлен», infrastructure_ready=true, delivery_ready=false. Только после проверки worker сохраняется полный успешный отчёт в `root/verification.json`. Обычная verify без skip также требует фактический worker. Контракт после запуска описан в [setup.md](setup.md). Broker end-to-end этим не подтверждён.

Не менять approval_policy для маскировки сбоя, не копировать rules вместо проверенного symlink и не создавать пустой config.toml. Не обновлять Codex вслепую. Предложение обновить CLI требует отдельного контрольного сравнения A/B/C на старой и кандидатной версии; только после доказанного исправления меняются pin и integrity. Workspace-write, Chromium sandbox, TLS и защиты macOS остаются включены.

При переносе старой установки с небезопасным root не правь работающий worker в фоне. Подготовь безопасную установку только после поручения на перенастройку, сохрани профили/состояние старой и повтори полный импорт/verify. Исправление навыка или подготовка ZIP сами по себе не разрешают замену установленного приложения.

Для штатного завершения ссылка auth.json удаляется в finally launcher. Frozen worker при таймауте использует killpg(SIGKILL), поэтому r5 дополнительно запускает фиксированный sbs-auth-guard в отдельной группе процессов с IPC. При закрытии канала он удаляет только ту же временную ссылку по inode, не читая её цель/credentials. Без подтверждения guard Codex не запускается. Normal exit, SIGTERM и hard group kill проверяются синтетическими процессами. Остановка всей машины или принудительное завершение самого guard остаётся вне гарантии; исходный auth.json не удаляется. Guard не добавляет новые allow-префиксы и не обходит sandbox.
