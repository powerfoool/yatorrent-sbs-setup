# Координатор на отдельной машине

## Настройка

Используй общую установку из SKILL.md: YaTorrent, внешний AIM2, private Codex/Node, Playwright/Chromium, exact rules, native executor-runtime.json, 11слотов, timeout1800, concurrency4. По умолчанию эта машина принимает Codex tasks наряду с ролью координатора. Не рассчитывай на файлы/авторизацию/утилиты других Mac. Поручение только собрать пакет не запускает эту настройку.

Дополнение `python3 scripts/coordinator_setup.py --plan` не меняет систему. `--apply --root ROOT` требует готовый общий runtime, ставит private JSON Schema2020-12 validator (закреплённые зависимости в отдельном Python venv), gws через Homebrew при отсутствии и private root/bin/gwsx. Этот standalone wrapper поддерживает `work`, `status work`, Sheets/auth/schema; сохранённые credentials лежат в вычисленной ~/.config/gws-corp-app либо --google-config владельца. Он не заменяет чужой глобальный launcher и не читает токены через LLM. Используй `export PATH=ROOT/bin:$PATH` в сессии координатора либо полный путь; не подставляй root автора.

Python≥3.10 проверяется до изменений; ранее созданный несовместимый coordinator venv сохраняется в backups и пересоздаётся выбранным supported Python. Wrapper и auth status запускают gws с cwd=/ и отклоняют существующий /.env, чтобы dotenv проекта/предков не мог вернуть чужой токен после очистки env. Файловые аргументы gws при необходимости передавай абсолютными путями.

Авторизация отдельная от Codex/AIM2. По умолчанию Sheets scope read/write: https://www.googleapis.com/auth/spreadsheets. Ни Drive, ни Gmail для обычной таблицы не требуются. Если вход уже доступен, проверь его и конкретную таблицу, не заставляй пользователя повторять OAuth без причины. gws auth status новых версий не показывает scopes: неизвестный write scope не считать подтверждённым. OAuth client Desktop предоставляет владелец вне ZIP: его локальный файл копируется в `<google-config>/client_secret.json` (по умолчанию ~/.config/gws-corp-app/client_secret.json), с правами0600; каталог0700. Не путать этот каталог с дефолтным ~/.config/gws из общего руководства. [официальная настройка Google CLI](https://github.com/googleworkspace/cli#authentication). Владелец завершает Google consent на этом Mac. Команда `gwsx work --confirm auth login --scopes https://www.googleapis.com/auth/spreadsheets`. Не копируй вход автора/другого аккаунта. При отсутствии клиента объясни, зачем нужен этот файл, и предложи использовать корпоративный Desktop client или создать собственный в Google Cloud.

`coordinator_setup` возвращает awaiting_google_login/ненулевой код, если вход недоступен. Успех означает только local tools/auth; не доказывает доступ к выбранному документу, запись, свежий worker или broker end-to-end. Для файловых входов/выходов --no-google пропускает Google; формат результатов согласуется всё равно.

## Понятный разговор и согласование

Считай пользователя новичком. Спрашивай о результате, не реализации. При первом запуске объясни одним предложением, что координатор прочитает пары, поручит сравнение исполнителям и вернёт оценки. Если список уже дан, не проси его повторно. Прежде чем разметить, прочитай метаданные листа и необходимые заголовки/строки.

Предложи компактный выбор и возможность собственного варианта:
1. Рекомендуемый при существующих колонках: «Итог в колонке оценки, подробный разбор в комментарии». JSON объясни как структурированный текст с полями, не требуй от пользователя знания формата.
2. «Отдельные колонки для итоговой оценки, качества левой/правой выдачи и причин выбора». Покажи будущие заголовки, образец строки, куда уйдёт полный разбор.
3. «Отдельный файл с результатами, таблицу не менять».

Согласуй словарь вердиктов (например левая/правая/равны/недостаточно данных), оценочную шкалу рубрики, причины победителя, URL/аспекты в подробностях, ошибку/неизвестные поля. Не навязывай новую шкалу вместо промпта пользователя. Предложение изменить структуру таблицы покажи конкретно: новые поля и точные диапазоны, существующие данные сохранить. Пользователь выбирает; уже согласованная запись каждой завершённой строки не требует нового подтверждения.

В private agreement.json сохрани schema_version1, approved=true **только после реального выбора владельца**, approval_note с его решением, spreadsheet_id/sheet_id/sheet_title, input_columns, outputs (колонка→JSON Pointer), output_schema, verdict translations/overwrite policy/ошибки. На resume используй тот же формат; изменение согласуй. Не представляй автоматически созданное approved=true как пользовательское согласие.

Пример **варианта для согласования**, не универсальные колонки:
```json
{
 "schema_version":1,"approved":false,"approval_note":"",
 "spreadsheet_id":"OWNER_DOCUMENT_ID","sheet_id":0,"sheet_title":"Фактическое имя листа",
 "input_columns":{"id":"A","query":"B","left_html":"G","right_html":"H"},
 "outputs":{"P":"/winner","V":""},
 "output_schema":{"type":"object","properties":{"winner":{"type":"string"},"winner_reason":{"type":"string"}},"required":["winner","winner_reason"],"additionalProperties":false}
}
```
outputs в helper — колонка→JSON Pointer: пустая строка означает весь JSON. Для декомпозиции можно сопоставить /left_score, /right_score, /winner_reason и другие **реальные** поля схемы. Предложенная схема должна содержать весь согласованный разбор бригадира, а не только краткий пример. Если нужны переводы winner, задай их в согласованной схеме/промпте либо в явно проверенном преобразовании; helper сам не переводит enum.

## Чтение входов

`gwsx work sheets spreadsheets get --params '{"spreadsheetId":"ID","fields":"spreadsheetId,sheets.properties"}'`

Разреши gid в фактическое имя листа: это не всегда Sheet1. Values get для точного диапазона, JSON argument передай как отдельный argv (не shell string с данными):
`gwsx work sheets spreadsheets values get --params '{"spreadsheetId":"ID","range":"Фактический лист!A1:V20"}'`

Input selection только query, region/device, две HTML, top5 и устойчивый source ID. Существующие человеческие/старые оценки не передавай бригадиру. Если ID нет, согласуй стабильную идентификацию и не используй один номер строки: сортировка меняет его. Для идентичных дублей нужен отдельный согласованный ID. HTML больших выдач не обрезай молча: пустое/усечённое/ссылка вместо HTML требует отдельного чтения и проверки исходника. Снимок входов/hash сохраняется локально; неизвестные важные поля уточни понятным вопросом.

## Задания и прогресс

Используй рубрику оценки, foreman/scout prompts пользователя или согласованный отдельный skill архив. Они не включены в установочный пакет и не должны быть придуманы. Координатор передаёт их текстом в задаче, либо доступную workers публичную ссылку на отдельный архив с SHA256. Google читает только координатор, URL обходят scouts. Один SBS/task по умолчанию; один payload item. При bulk100 задача не превращается в100одновременных исполнений.

`coordinator_data.py prepare --agreement agreement.json --input pair.json --foreman foreman.md --scout scout.md --output task.json` создаёт offline envelope/publication без сети. pair содержит id/query/left_html/right_html и при наличии region/device/top5. Stable item ID зависит от входа, рубрики, схемы. В wire отправляй **только** .publication: envelope metadata не входит в broker API. Публикацию сохраняй до POST, receipts/task_id после проверки ответа. Рабочие команды browser обнаруживаются на worker: root другой машины не переносится. Нельзя считать installed descriptor на координаторе конфигом всех peers.

Проверь актуальный API и безопасный доступ к очереди результатов по [broker.md](broker.md). Скрипт prepare не отправляет задачи; сетевой producer/consumer агент ведёт по этому контракту с private journal. Штатный YaTorrent CLI такого координатора не предоставляет. Это навык агента с переносимыми локальными помощниками, не автономный демон с обещанием survive закрытого чата. Если нужен постоянный запуск после закрытия агента, это отдельная согласованная служба; не выдавай активный чат за daemon.

Следи за прогрессом, но не придумывай недоступные стадии. Сообщай пользователю коротко подтверждённые количества/ошибки и необходимые решения. Не проси его понимать lease/fingerprint — объясни «сервер временно выдал результат», «результат сохранён», «таблица обновлена». Получение/ACK/Google-write имеют отдельные состояния и восстановление.

## Запись после каждого завершения

Сохрани delivery до ACK, проверь source/task/item identity, per-item completion и JSON Schema2020-12 через `ROOT/bin/coordinator-validate agreement.json validated-final.json`. Перед отправкой проверь саму схему `ROOT/bin/coordinator-validate agreement.json`. Проверка обязательна; отсутствие validator не заменяется ручным просмотром. Remote $ref нужно разрешить в локальную согласованную схему до intake; validator не загружает внешние ссылки. Нет output/failed item — отдельная обработка ошибки, не искусственный winner.

Найди текущую строку по устойчивому ID; перечитай входы, сравни snapshot/hash и целевые значения с согласованной overwrite policy. При сортировке следуй текущей строке; изменённый HTML/запрос, дубликат ID, новая чужая оценка — конфликт, без автоматической перезаписи.

`coordinator_data.py project --agreement agreement.json --input validated-final.json --row CURRENT_ROW --output cells.json` создаёт **только тело** Sheets values.batchUpdate: RAW, точные ячейки, экранированное имя листа, полные значения. Он не валидирует output_schema и не доказывает identity/ACL/пользовательское согласие; эти условия выполняет координатор перед запуском. Missing field, >49000символов/ячейку, пересечение input/output отклоняются. При большом JSON согласуй отдельный файл/дополнительные поля; не обрезай автоматически.

После сохранения write plan:
`gwsx work --confirm sheets spreadsheets values batchUpdate --params '{"spreadsheetId":"ID"}' --json <BODY_AS_SINGLE_ARG>`.
Без --confirm wrapper возвращает preview/exit3 и ничего не пишет. Значение --confirm означает техническую команду после уже полученного согласия на этот формат; не требование спрашивать заново каждую строку. Передай JSON содержимое cells.json программно одним аргументом, без подстановок пользовательских строк в shell. RAW защищает текст вида =... от выполнения как формулы. Проверь updated ranges/значения и перечитай точные ячейки. Только readback подтверждает written. При новой структуре сначала выполняется согласованный metadata batchUpdate/headers, readback, затем values.

На restart replay write_pending без append, новое получение результатов только после durable replay и в разрешённой области. Ни успешный ACK, ни exit0 gws preview не означают запись. Итог пользователю — ссылка/файл и подтверждённые результаты, сколько пар осталось/ошибок, без raw tokens и технических логов.
